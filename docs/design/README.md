# Дизайн DejaView: каталог и воспроизводимый экспорт

Локальный FIG разобран: **3 687 узлов, 88 верхнеуровневых фреймов, 66 нумерованных экранов, 34 переменные и 13 текстовых стилей**. Результаты: [каталог](screens.md), [машинный каталог](screens.json), [токены](tokens.md), [JSON токенов](tokens.json), [расхождения с PDF](screen-map.md). Это извлечение структуры и данных, не завершённая визуальная приёмка.

Подключённая Figma подтвердила доступ к макету и вернула часть метаданных. Для семи frames получены ссылки на PNG, однако скачивание вернуло HTTP 202 с пустым телом; **валидных PNG пока нет**. Затем API сообщил об ограничении числа запросов. Полная коллекция точных PNG/SVG остаётся незавершённой. В репозитории нет подменяющих её сгенерированных картинок.

## Что находится в приватном наборе

`.local/design/offline/` содержит manifest, полный декодированный документ/schema, variables/text-styles и `screens/<node-id>.json` с поддеревом каждого frame. В этом FIG нет вложенных bitmap-ресурсов; это не гарантирует отсутствие внешних изображений в онлайн-файле. `.local/` игнорируется Git и не прикладывается к публичным PR. В макетах есть заполненные пользовательские данные — см. [политику](../privacy.md).

## Повторить извлечение из FIG

Скопировать доступный приватный FIG в `.local/input.fig`, затем из корня проекта:

```text
npm ci --prefix tools/design --ignore-scripts
node tools/design/extract-fig.mjs .local/input.fig .local/design/new-export
npm test --prefix tools/design
```

Выходной каталог должен быть новым/пустым и находиться внутри `.local`; symlink/junction-переходы запрещены. Исходник не изменяется. Используется зафиксированный `openfig-core@0.4.1` и lockfile, без install scripts. Это сторонний декодер локального формата, а не официальный renderer Figma. При новой версии формата перепроверить количество узлов/frames и значения токенов; parser не должен молча заменять недоступные поля.

## Точные PNG/SVG через локальный плагин

Подготовлен инструмент [tools/figma-export](../../tools/figma-export/code.js). Он читает все страницы или выбранную страницу, рекурсивно проходит sections, выбирает внешние frames, экспортирует PNG 1× и SVG с контурами текста. Внутренние frame-контролы остаются в JSON дерева, а не превращаются в отдельные экраны. Номера не используются как имена файлов: nodeId предотвращает коллизии вариантов.

1. В Figma Desktop открыть доступный файл. В меню Plugins → Development создать локальный plugin с UI. Сохранить выданные файлы в приватном `.local/figma-created/`. Это нужно для получения назначенного Figma plugin ID; публиковать плагин в Community не требуется.
2. Из корня проекта выполнить:

```text
node tools/figma-export/build.mjs .local/figma-created/manifest.json
node --test tools/figma-export/export.test.mjs
```

3. В Plugins → Development импортировать manifest из `.local/design/plugin/manifest.json`, запустить DejaView private export. При конфликте уже зарегистрированного development ID выбрать созданный manifest вместо старого. Нажать «Выгрузить», затем «Сохранить ZIP».
4. Сохранить архив в приватное хранилище, локально — в `.local/design/`. Проверить manifest: frame count, наличие PNG/SVG у каждого frame, массив errors. Любая ошибка означает неполную выгрузку. Открыть изображения всех экранов своей роли и сравнить с оригиналом.
5. Если объём превышает 256 МиБ, перезапустить плагин и выгружать по одной странице. Пустой/оборванный архив не считается результатом. При изменении онлайн-файла количество frames может отличаться от локального снимка: сверить nodeId и отметить новые/удалённые узлы.

Архив включает деревья слоёв с размерами, layout, fills/strokes/effects, текстами и style segments, reactions, component/variable references; локальные variables/collections/text/paint/effect/grid styles; доступные bitmap fills. Данные comments, edit history, account identities, определения внешних библиотек и файлы шрифтов не извлекаются. SVG не заменяет исходный editable text, поэтому JSON сохраняется отдельно. Данные анимации, специфичные для новых API, могут не входить в allowlist полей — полный decoded FIG остаётся дополнительным источником.

Плагин не изменяет nodes, не читает аккаунт, не запрашивает токен и не делает сетевых запросов. Manifest запрещает внешнюю сеть. ZIP формируется локально без внешних CDN. Это не делает содержимое ZIP публичным: реальные данные могут быть нарисованы в пикселях. Figma и её редактор по-прежнему являются внешним сервисом, в котором уже находится дизайн.

Официальная документация: [exportAsync](https://developers.figma.com/docs/plugins/api/properties/nodes-exportasync/) и [plugin manifest/networkAccess](https://developers.figma.com/docs/plugins/manifest/). Локальная проверка инструмента выполнена на mock API и независимом ZIP reader; **запуск в Figma Desktop и полный визуальный экспорт ещё не выполнены**.

## Передача разработчикам

Публично передаются только каталог, проверенные токены и код инструмента. Dev 3 координирует полноту экспорта; каждый Dev получает приватные frames своих задач и проверяет их визуально. Перед публикацией производных скриншотов заменить персональные значения синтетическими и просмотреть пиксели. Полный file key и временные asset URLs не нужны в задаче или публичной документации.
