## D2-01 HTTP и персональный контракт

**Файлы:** `core/network`, `core/contracts/personal`; общие модели — согласованный PR Dev 1. Подготовить `PersonalMoviesRepository` и Fake для Dev 1 в D1. HTTP-клиент получает cookie abstraction Dev 4; он не хранит отдельную независимую сессию.

Настроить base URL `/api/v1/`, JSON, multipart, отмену запроса, таймауты и общую обработку ошибки. Сохранить HTTP-код, `code`, `field`, `Retry-After`. Различать offline, transport timeout, 503, malformed response. Логировать только безопасную диагностику: без тел auth-запросов, cookie, query текста поиска и содержимого медиа. Для ошибки от nginx не предполагать, что тело всегда JSON.

Таймаут должен включать загрузку и обработку, а не обрывать видео на лимите обработки ML. Конкретные значения согласовать со стендом D2 и записать в конфигурации. Не вводить автоматический повтор POST search или auth: после обрыва неизвестно, обработал ли запрос сервер. Ручной повтор разрешён пользователю; `429` ждёт Retry-After.

**Проверки:** MockWebServer для 200 JSON, 204 без тела, 400 field error, 401, 403, 413, 415, 422, 429, 503 и не-JSON ответа. Отмена не становится AppError. Cookie отправляется только правильному origin/path; protected 401 вызывает один invalidation event. **Выход:** HTTP module и test fixtures для всех. До готовности стенда все эти проверки выполняются локально.

## D2-02 CI и качество

Подключить [quality gate](../testing.md): реальные Android tasks, отчёты, coverage, проверки границ и CI с SDK. Repository gate не проверяет Android. Выполнить отрицательный прогон на нарушении правила, затем убрать контрольное нарушение.

**Файлы:** `.github`, `scripts`, `core/testing`. Создать PR workflow: фиксированный JDK из version catalog/toolchain, Gradle cache, lint/стиль, unit tests, сборка demoDebug и prodDebug. Проверить реальные имена tasks после создания flavor; ожидаются `testDemoDebugUnitTest`, `testProdDebugUnitTest`, `lintDemoDebug`, `lintProdDebug`, `assembleDemoDebug`, `assembleProdDebug`. Не копировать `testDebugUnitTest`, если такой задачи уже нет.

Добавить PR template с UC, включёнными/отложенными альтернативами, способом проверки, скриншотом UI и backend-зависимостями. Проверка Gradle-графа запрещает feature implementation → feature implementation; разрешены `search-api` и `core/contracts`. Production graph не содержит `core/testing`. Тестовые ресурсы и demo fixtures не заменяют реальную сеть в prod.

CODEOWNERS и branch protection — возможные настройки владельца repo, не обязательные условия текущего мобильного процесса. Несколько владельцев в строке не означают обязательный аппрув каждого. Ревью потребителя желательно; отсутствие ревью не блокирует локальную работу и не заменяет тесты. Ключ подписи не кладётся в git; инфраструктура release workflow для внутреннего APK, публикацию в магазин не выполнять.

**Выход:** зелёный PR CI, артефакты с SHA/variant, воспроизводимая команда для Windows (`.\gradlew.bat ...`) и Linux (`./gradlew ...`). **Приёмка:** намеренно нарушенный test/межмодульный импорт даёт красный job; реальные проверки запускаются, а не отмечаются пропущенными. Эмуляторный smoke обязателен до поставки, не обязательно в каждом PR.

## D2-03 Поиск по изображению

**UC-07 частично, FR-05/04. Экраны:** 2.1, 2.1б, 2.3, 2.4, 2.8, 3.1, 3.3, 3.4, 3.5а; камера/crop перенесены; в Figma 2.3а — отказ доступа к камере (см. карту дизайна). **API:** `POST /search/image`, multipart `file`. **Модуль:** `search-image`.

Системный picker одного изображения → импорт через MediaStore → превью → submit. Поддержать JPG/JPEG, PNG, WEBP до 10 МиБ, cancel picker, замену файла, недоступный URI, повреждённый файл. Нет камеры, crop и буфера обмена в этом этапе. Возвращать SearchCompletion оболочке; историю напрямую не писать.

На upload показывать байты/прогресс, затем Processing; cancellation освобождает HTTP и временный файл. После ошибки оставить доступный draft для ручного повтора. «Это не тот фильм» — общая навигация к альтернативным режимам, не новый backend endpoint.

**Приёмка:** валидный файл → один фильм; пустой results → общий empty; 10 МиБ проходит, +1 байт не отправляется; 401 идёт через общую сессию; 413/415/422/503 корректно отображаются; поворот/замена не показывают старый ответ. Проверить на реальном устройстве изображение из внешнего provider, а не только локальный путь. **Выход:** UI, Fake, real adapter, mapper и тесты в одном модуле.

## D2-04 Два списка

**UC-11/12, FR-09. Экраны:** действия 3.1/4.1; списки 5.1, 5.1а, 5.1б, 5.2. **Модуль:** `library`. **Целевой API:** `GET /movies/{movie_id}/my-state`; `GET /users/me/watchlist`, `GET /users/me/watched`; `PUT/DELETE /users/me/watchlist/{movie_id}`, `PUT/DELETE /users/me/watched/{movie_id}`.

В D1 зафиксировать адаптер существующих обработчиков backend main с путями `/users/me/lists/{list_type}` и `/users/me/movies/{movie_id}`. Для текущего серверного контракта реализовать отдельный явно выбранный adapter: его DTO `movies,total` не равны целевым `items,page,total_pages,total_items`. Список адаптеров фиксируется сборкой, не перебором URL по 404.

Сначала Fake и общий personal state, затем два списка, сортировки date/title/rating по обоим направлениям, пагинация по 24. Поиск `q` не реализовывать: Swagger помечает его неиспользуемым в мобильном UI. По изменению sort очистить страницу и игнорировать поздний ответ старого запроса.

Реализовать idempotent setMembership; один фильм может быть в двух списках. Повторное нажатие удаляет выбранную отметку, не меняя другую. После успеха публиковать состояние для Dev 1, обновлять список; undo возвращает предыдущее значение отдельным запросом. Переход в фильм — только MovieRoute. Сессионная смена очищает память с personal state.

**Приёмка:** 0/1/24/25 элементов; page boundaries; все sort-параметры; 204 не парсится как JSON; timeout не отображается как подтверждённый успех; двойное нажатие не создаёт конкурирующие toggle; logout не оставляет чужой список; действие из карточки появляется здесь без перезапуска. **Выход:** одна реализация PersonalMoviesRepository, Fake и контрактный тест, который может запускать Dev 1.

## D2-05 Оценки

**UC-13 только часть оценки, FR-10 частично. Экран:** 4.3 по Figma; 4.2 — карточка после прокрутки, редактор отзыва 4.4 не входит. **API:** `PUT /movies/{movie_id}/my-rating` с `rating`, `DELETE /movies/{movie_id}/my-rating`. Summary загружает Dev 1 через свой API, а вы публикуете успешное изменение в personal state.

Передавать желаемую оценку 1–10 или null для удаления, не `0`. Создать/изменить/удалить оценку, показать подтверждение и ошибку сохранения. Не менять watched при оценке. Рейтинг отражается в списке; карточка после изменения обновляет summary. Координация — через согласованный state/invalidation в personal contract, не общий глобальный event bus с произвольными строками.

**Приёмка:** границы 1/10, отклонение 0/11; изменение 5→8; удаление; повтор; отсутствие сети; 401; вход гостя и выполнение ожидающего действия. Неуспех сохраняет предыдущее значение. Если endpoint отсутствует на стенде, зарегистрировать блокер поставки, а не оставлять успешный Fake в prod.

## D2-06 Проверка контрактов

Сверить реальные ответы стенда с fixtures всех владельцев. Выполнить проверки nullable/required полей, multipart `file`, числовых ID, ответов 204, ошибок и пагинации. На D8 заморозить hash выбранного API-контракта и список поддержанных операций. Сохранить минимальный обезличенный отчёт: endpoint, статус, дата, build/commit стенда при доступности, ожидаемый/полученный результат.

**Приёмка:** собственные image/library/rating adapters проверены; Dev 1/3/4 предоставили проверки своих; CI не зависит от постоянной доступности live backend. Отдельный ручной/live smoke доказывает совместимость, локальные fixtures — воспроизводимость.

## Передачи и релиз

D1: PersonalMoviesRepository + Fake для Dev 1, HTTP stub для всех. D2: реальный транспорт и формат ошибок. D6: список и изменения состояния для карточки. D7: rating. От Dev 3 получить MediaStore; от Dev 4 — cookie store с семантикой logout; не делать свои копии.

D9–D10, 12 ч: вести проход [приёмки](acceptance.md), собрать подписанный тестовый APK, проверить SHA/variant и исключить demo bindings. Регрессию распределяют все четверо, вы не становитесь единственным тестировщиком. Следующий этап: отзывы/реакции и кадр с камерой/crop/clipboard — P2-04/05/06.
