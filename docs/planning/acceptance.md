# Приёмка первой поставки DejaView Android

Этот список проверяет сокращённый MVP из [плана](README.md). Для каждого пункта сохраняются variant/build SHA, устройство/API, сценарий, ожидаемый и фактический результат. До выполнения статусы всех пунктов — **не проверено**. Создание этих документов не является прохождением тестов приложения.

## Контрольные точки

| Точка | Условие прохождения | Ответственный |
| --- | --- | --- |
| G1 конец D1 | Demo/prod собираются, контракты v1 согласованы, у каждого есть Fake | Dev 1, все владельцы |
| G2 конец D2 | Real login/session и text smoke либо точный backend blocker; принято решение по API | Dev 4, Dev 1, Dev 2 |
| G3 конец D5 | Четыре режима дают found/empty/error на Fake; обязательные endpoint проверяются на стенде; список связан с карточкой | Все |
| G4 конец D8 | Вся первая поставка работает в prod на стенде, нет runtime Fake, feature freeze | Все; Dev 2 собирает отчёт |
| G5 конец D10 | Обязательные сценарии ниже пройдены на итоговом APK, нет блокирующих дефектов | Ментор принимает, команда предоставляет доказательства |

G4 не пройдена из-за backend — допустима только явно обозначенная demo-поставка. Она не называется завершённым real MVP.

## Граничные проверки

| Область | Минимальные случаи |
| --- | --- |
| Текст | 0/2/3/250/251 символ; пробелы; Unicode; русский/английский; два submit подряд |
| Изображение | Валидные JPG/PNG/WEBP; 0 байт; лимит и +1 байт; неверное расширение/MIME; недоступный URI |
| Видео | MP4/MOV/WEBM с поддерживаемым содержимым; 30 000 и 30 001 мс; 50 МиБ и +1 байт; повреждённый/неподдерживаемый codec |
| Звук | MP3/WAV/OGG/M4A; 10 000 и 10 001 мс; 20 МиБ и +1 байт; отказ permission; реальный M4A контейнер |
| Списки | 0/1/24/25 записей; все согласованные sort; пустая последняя страница; поздний ответ прежней сортировки; 204 без JSON |
| Оценка | 1/10; 0/11 отклоняются; null удаляет; network failure сохраняет старое значение |
| Данные | null poster/year/overview; пустой cast; 404 фильма; неизвестное дополнительное поле; нарушение required field даёт controlled error |
| HTTP/сессия | 400/401/403/413/415/422/429/500/503; безопасная обработка Retry-After; чужой host; не-JSON body; cancel; late Set-Cookie |

## Уровни тестирования

Unit-тесты проверяют правила и гонки состояния: длины/лимиты, отмену, stale response, idempotent desired state, session transitions. Mapper/MockWebServer проверяют реальные поля, 204, multipart и ошибки. Не нужен тест на каждый getter или копия реализации в assert.

Инструментальные или ручные проверки на устройстве обязательны для picker/content URI, Keystore, Room, микрофона и media playback. Минимум один физический аппарат с микрофоном и один эмулятор на выбранной нижней границе API; при возможности добавить актуальный API уровень. Конкретные модели/API фиксируются D1. Для UI: узкая ширина, увеличенный шрифт, клавиатура и системные отступы.

CI на каждом PR собирает demo/prod, запускает unit/contract tests, lint/стиль и проверяет границы модулей. Live backend не должен делать CI случайно красным; отдельно проверяется staging smoke. Перед поставкой обязательна установка именно итогового APK, а не прошлой локальной сборки.

## Дефекты и решение о поставке

Блокирующие: crash основного сценария, невозможность любого из четырёх обязательных режимов при валидном вводе, login/list/rating не работают, утечка данных между пользователями, скрытая Fake-подмена, неосвобождённая запись микрофона, неработающая CAPTCHA после challenge. Неблокирующие визуальные дефекты можно принять только с явно записанным отклонением и владельцем.

На D9–D10 у каждого 12 ч на исправления, взаимную регрессию и повтор проверки. Эти 48 командных часов не используются для добавления отложенных функций. Release notes перечисляют включённые сценарии, известные ограничения и необходимость готового подтверждённого аккаунта.
